変換結果から福山通運の送り状ソフトに取り込むCSV（エントリーデータ）を生成する機能の仕様。
ユーザーが以前に検討した内容の保存版（2026-06-12受領）。

## 実装状況（2026-06-12 実装済み）

WEBツール（`index.html`）の「🚚 送り状CSV」ボタンとして実装。
マスタはCSVファイルではなく **`CONFIG.invoiceCsv`**（index.html内 ⑪）に埋め込み管理。

**操作フロー:** 🚚ボタン → 編集可能なプレビュー表が出る → セルを手修正 →
「📥 CSVをダウンロード」で保存（プレビューを見て確認・修正してから出力する2段階方式）。

### まとめ梱包ルール（ニオイしま栓！の2ケース1梱包）

2ケース以上を同じ場所・同じ日に届ける場合は2ケースずつ1梱包になる。
送り状（CSV行）は梱包単位で分割し、各行の個数=1。品名記事2が「2ケース1梱包」に変わる。

| 数量 | 出力される送り状 |
|---|---|
| 1 | 1ケース ×1件 |
| 2 | 2ケース1梱包 ×1件 |
| 3 | 2ケース1梱包 ×1件 ＋ 1ケース ×1件 |
| 4 | 2ケース1梱包 ×2件 |
| 5 | 2ケース1梱包 ×2件 ＋ 1ケース ×1件 |

マスタでは**全製品が同じ項目**を持ち、数字を変えるだけで設定できる:

```
まとめ梱包: 1,                       ← 1=まとめない / 2=2ケースずつ1梱包 / 3=3ケースずつ…
まとめ梱包の品名記事2: '',           ← まとめた行の品名記事2（まとめ梱包が2以上のとき使われる）
```

ニオイしま栓！は `まとめ梱包: 2` ＋ `まとめ梱包の品名記事2: '2ケース1梱包'`。
それ以外の製品は `まとめ梱包: 1`（分割なし、個数=数量のまま）。

### 実装上の取り決め

- ファイル名: `◯月◯日出荷日分CSVエントリーデータ.csv`（日付は出荷日）
- 文字コード: **Shift-JIS（CP932）**・改行CRLF（送り状ソフトがWindows用のため。encoding-japanese使用）
- 日付形式: **8桁数字 `yyyymmdd`**（配達指定日・出荷日付・登録日付。
  当初は`yyyy/mm/dd`だったがiS-2の取込でエラーになることを確認し2026-06-13に変更）
- **ゆうパック行は出力しない**（`excludeCarriers`。除外件数はプレビューの注記に表示）
- マスタ未登録の商品はプレビューの注記で警告し、荷送人コード・品名記事を空欄のまま出力
  （プレビューで手入力すれば補える）
- 製品名のマッチングは完全一致だが、＆/&（全角/半角）は同一視する
- **必須項目チェック**: `CONFIG.invoiceCsv.requiredColumns`（電話番号/住所/住所2/名前/郵便番号/
  荷送人コード/個数/配達指定日/出荷日付/元払区分）が空白の行があると、プレビューで赤表示になり
  **CSVダウンロードがエラーで止まる**（プレビューで手入力すれば保存できる）
- **出荷日ガード**: 「📅出荷日を設定」未実行（出荷日セルが空白の行がある）だと
  Excel保存・送り状CSV・印刷のいずれもエラーで止まる
- ヘッダー行（列名）は既定で出力（`includeHeader: false` で外せる。ソフト側の取込設定に合わせる）
- 配送可能最短日数マスタは作らない（既存のLEADTIME定数＋出荷日設定ボタンが同じ役割）
- 輸送商品コード時間指定マスタは `timeCodeMaster` として枠だけ用意（現データに時間指定が無いため未使用）

### 要確認（実物での取込テスト時）

- ~~日付形式~~ → **確認済み: 8桁`yyyymmdd`必須**（yyyy/mm/ddはiS-2でエラー。2026-06-13修正済み）
- ヘッダー行の要否（ソフトの取込設定次第）
- 住所1=都道府県のみ、の分け方で問題ないか（ソフト側で住所1必須チェックがある場合など）
- ジェット＆ビーズの荷送人コード・品名記事（受領した表に無かったためリーシングと同じBで仮置き）
- まとめ梱包行の「個数」が1でよいか（1梱包=送り状1件として実装）

## 運用メモ（送り状ソフト・運送会社）

- 運送会社は**基本 福山通運**（安いため）。**沖縄県や離島は高額になるためゆうパック**を使う仕組み
  （→ ツールがゆうパック行を送り状CSVから除外しているのはこのため）
- 福山通運のソフトは **iS-2（Windowsソフト）**。**iS-X（WEBアプリ）**もあり今後移行予定だが、
  **CSVを作って読み込ませる運用は変わらない**
- **保険金額**: iS-2では手入力できないが、**CSVエントリーなら入力できる**
  （取込後の修正はグレーアウトしていて不可）
- **重量・才数**: iS-2/iS-X とも**強制0になる**（CSVで何を入れても意味がない→空欄でOK）

## マスタの役割分担

- **製品と荷送人マスタ** — 送り主情報の管理（荷送人名・荷送人コードの自動設定）
- **製品と品名記事マスタ** — 品名情報の管理（品名記事1～3の自動設定、梱包形態も保持）
- 分離の利点: 荷送人情報と品名情報を独立管理／それぞれの更新が容易／データの重複を削減
